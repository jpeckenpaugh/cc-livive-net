# M2a — Coordinates and move tables

**Read first:** `concept.md` §3, §4 (`corner_twist`, `edge_flip`,
`slice_combination`), §6, §12 (coordinate and move-table tests),
`docs/DECISIONS.md`, and the existing core code.

**Mode:** question-first. Return questions before writing files. No git. All
cargo commands via `./scripts/docker.sh`.

## Goal

The coordinate layer the solvers stand on: dense integer encodings with
bidirectional conversion, plus generated move tables and a versioned on-disk
format. No search yet.

## Coordinate placement

Two crates need coordinates, and the core cannot depend on the solver:

- **`color-cube` (core, `no_std`)**: `Cube::corner_twist() -> u16`,
  `Cube::edge_flip() -> u16`, `Cube::slice_combination() -> u16`, plus the
  setters `set_corner_twist`, `set_edge_flip`, `set_slice_combination`
  (`-> Cube` or `&mut self`; your call, but be consistent). Range-check the
  input and document a panic on out-of-range values.
- **`color-cube-solver` (std)**: `coords` module with all six coordinates,
  reusing the three core helpers rather than reimplementing them:
  `twist`, `flip`, `slice`, `cp_rank`, `ep8_rank`, `sp_rank`, and their
  setters. `set_*` reconstructs a valid cube (other coordinates preserved where
  they are independent; document what is preserved).

## Definitions (fix these exactly)

- `twist = sum(co[i] * 3^i)` for `i = 0..6` (seven terms, `co[7]` implied by
  the mod-3 sum), range `0..=2186`. `set_twist` writes `co[0..7]` from the
  base-3 digits and `co[7] = (3 - sum % 3) % 3`. The eight-term phrasing in an
  earlier draft of this brief was wrong.
- `flip = sum(eo[i] * 2^i)` for `i = 0..10` (eleven terms, `eo[11]` implied),
  range `0..=2047`.
- `slice` = rank of the 4-subset of positions `p0<p1<p2<p3` holding pieces
  `FR,FL,BL,BR`, using the combinadic
  `C(p0,1) + C(p1,2) + C(p2,3) + C(p3,4)`; range `0..=494`. Document the
  inverse.
- `cp_rank` = Lehmer rank of the 8-corner permutation, `0..=40319`.
- `ep8_rank` = Lehmer rank of the permutation of the eight U/D edges in
  positions `0..7`, `0..=40319`.
- `sp_rank` = rank of the order of the four middle-slice edges in positions
  `8..11`, `0..=23`.

`SLICE_SOLVED = 494` (the combinadic of `{8,9,10,11}`). Do not "fix" it to
zero; pruning tables start their BFS from 494.

Setter semantics (important):

- Core setters are *raw*: `set_corner_twist`/`set_edge_flip` touch only `co`/`eo`
  and preserve the rest, so they keep a valid cube valid.
  `set_slice_combination` rearranges `ep` only, using a stable partition that
  preserves the middle-edge order (`sp`), but may change `ep` parity and thus
  produce an invalid cube. Document this; do not silently repair in the core.
- Solver setters (`set_twist`, `set_flip`, `set_slice`, `set_cp`, `set_ep8`,
  `set_sp`) must return a valid cube for any in-range input. They repair
  permutation parity by swapping within a set that does not disturb the
  coordinate just written (for `set_slice`, swap two middle pieces and accept a
  different `sp`; for `set_cp`/`set_ep8`, swap within the corresponding
  permutation), and they document which other coordinates may change.
- Add `set_cp_ep8(cp_rank, ep8_rank)` in the solver so phase-2 table generation
  can realise both at once with one repair, instead of relying on call order.

All coordinate getters are total for a valid cube. `ep8` and `sp` are only
meaningful when the slice is clean (the four middle pieces occupy positions
`8..11`); callers must not use them off `G1`, and the move tables below encode
that restriction (D018).

## Move tables

`color-cube-solver/src/tables.rs`:

- `move_twist: Vec<u16>` shape `2187 x 18`
- `move_flip: Vec<u16>` shape `2048 x 18`
- `move_slice: Vec<u16>` shape `495 x 18`
- `move_cp: Vec<u16>` shape `40320 x 18`
- `move_ep8: Vec<u16>` shape `40320 x 18`
- `move_sp: Vec<u8>` shape `24 x 18`

Flat, row-major, indexed `coord * 18 + move`. Generated by realising a cube
from the coordinate, applying the move, and reading the coordinate back — no
hand transcription.

`ep8` and `sp` cannot be represented after a non-`G1` move (a middle-slice piece
leaves the slice). Keep the `18`-wide shape, but fill the eight non-`G1` columns
with `u16::MAX` / `u8::MAX` sentinels, export `PHASE2_MOVES` (the ten G1 moves:
`U,U2,U',D,D2,D',R2,L2,F2,B2` as indices `0,1,2,9,10,11,4,7,13,16`), and treat
those entries as undefined. Every `move_ep8`/`move_sp` test iterates only
`PHASE2_MOVES`.

## On-disk format

`color-cube-solver/src/bin/gen-tables.rs` and a loader:

- One bundle: `tables/cc-tables-v1.bin` (path overridable by
  `COLOR_CUBE_TABLES`, which names a **directory**, default `./tables`).
- Layout, all little-endian, no padding:
  `magic b"CCLT"`, `u16 version = 1`, `u32 table_count`,
  `u64 payload_len`, `u64 param_hash`, `u64 checksum`, then a table directory
  (`u32 id, u32 rows, u32 cols, u8 width` per table), then the payloads
  back-to-back in id order `twist=1, flip=2, slice=3, cp=4, ep8=5, sp=6`.
- `checksum` is FNV-1a 64 over the payload only. `param_hash` is FNV-1a 64 over
  one frozen conventions literal (twist/flip/slice definitions, face and move
  order, format version, table ids and widths); keep that literal in a single
  `const` so the hash means something.
- `gen-tables` writes to a temp file in the same directory and renames it into
  place, prints elapsed time and byte size per table, and is idempotent:
  writing the same parameters twice produces byte-identical files.
- Loader errors: `TablesMissing`, `TableCorrupt` (bad magic/version/hash,
  checksum, dimension mismatch, unknown id). Do not panic on a corrupt file.
- `tables/` is gitignored already.

## Tests (must all run green)

1. Round-trip every value of `twist` (2187), `flip` (2048), `slice` (495),
   `sp` (24), and all 40320 ranks for `cp` and `ep8`. Fast enough for CI.
2. Solver setters: for every value of `twist`, `flip`, `slice`, `sp`, and all
   40320 `cp`/`ep8` ranks, `set_*` yields `is_valid()` and
   `get(set(v)) == v`. Core raw setters: `set_corner_twist`/`set_edge_flip`
   preserve validity; `set_slice_combination` is documented as raw (it may
   break parity) and is tested only for the subset/order it writes.
3. Move-table agreement: for sampled coordinates (and exhaustively for
   twist/flip/slice/sp), realise, apply, read, compare.
4. Composition: `table[table[x][A]][B] == apply A then B` for sampled pairs.
5. Determinism: generating twice yields identical bytes; header parses back to
   the right dimensions; flipping one payload byte yields `TableCorrupt`.
6. Cross-check: on 1,000 `Cube::from_seed` cubes, `twist()` equals a
   recomputation from `co`, and `slice()` equals a direct scan of where the four
   middle edges sit.

Table provisioning for tests: one integration binary owns the table-backed
tests, generates the bundle once into `std::env::temp_dir()/cc-tables-<pid>`
behind a `OnceLock`, and reuses it for every test in that binary. Do not require
a committed artifact and do not have several test binaries race to generate it.
Report the generation wall time; if debug-mode generation exceeds ~30 s, say so
and propose a cached `target/` artifact instead.
