# M6 — Optional optimal oracle

**Read first:** `concept.md` §9.3, §12 (optimality spot checks, superflip),
§14 M6; `docs/DECISIONS.md`; `docs/SOLVERS.md`; the solver crate.

**Mode:** question-first. Return questions before writing files. No git. Use
`./scripts/docker.sh`.

## Goal

An IDA* optimal solver behind a CLI feature flag that can prove distances,
including **superflip = 20 HTM**, without affecting the default build, tests, or
wasm.

This is explicitly optional and may be slow. Correctness and honest reporting
matter more than speed.

## Design

- New module `optimal.rs` in `color-cube-solver`, gated by a Cargo feature
  `optimal` (default off). The CLI gets an `optimal` subcommand behind a
  passthrough feature.
- Pattern databases (u8, `0xFF` unvisited), generated by `gen-tables --optimal`
  into `tables/cc-optimal-v1.bin` (magic `b"CCOP"`, version 1):
  1. **corner**: `cp_rank * 2187 + twist` → 88,179,840 entries.
  2. **edgeA**: six fixed edge pieces and their orientations in any six of the
     twelve positions → `12P6 * 2^6 = 42,577,920` entries.
  3. **edgeB**: the complementary six edge pieces → 42,577,920 entries.
- Partition the edges deterministically (e.g. pieces `0..6` and `6..12`) and
  document that the partition is arbitrary but frozen.
- Heuristic: `max(corner, edgeA, edgeB)`. Do **not** sum the edge tables; a face
  turn can move pieces from both groups, so summation is not admissible. State
  this explicitly in the docs.
- IDA* with:
  - iterative deepening from `h`;
  - ascending move order, same-face pruning, opposite-face canonical order
    (D014);
  - a bounded transposition table if it helps (memory-bounded, optional);
  - a hard depth cap of 20 and a wall-clock limit.
- `IdaStar` implements `Solver` with `optimal: true`, `phases: None`, and
  returns `NoSolutionWithinLimits` rather than a wrong answer.
- Replay-verify every solution as usual; an optimal claim additionally means
  the search exhausted all shorter depths.

## Feasibility gate (do this before polishing)

1. Generate the tables in release and report size, wall time, and peak RSS.
2. Print `h(superflip)` and run the oracle on superflip with a 5-minute budget.
3. Also run 20 random cubes with a 5-minute budget each.
4. Report nodes/s, depths found, and whether superflip = 20 was **proved**.

If superflip cannot be proved within 5 minutes on the reference machine, stop
and report the measurement. Do not weaken the heuristic's admissibility to make
it faster, and do not hard-code 20.

## Acceptance

- Feature off: default build, `./scripts/check.sh`, and wasm are unchanged.
- Feature on: `optimal --seed N`/`--moves` returns a replay-verified solution and
  claims optimality only after exhausting shorter depths.
- Superflip: either proved at 20 (distinct 20-move generator, not a copied
  fixture) or an honest failure report with numbers.
- Spot checks where optimal distance is cheap: cubes scrambled with `k` random
  moves for `k = 1..5` must return `≤ k`, and for a sample where Kociemba's
  length equals the oracle's, record agreement.
- Optimisation tests are `#[ignore]` by default and never run in `check.sh`.

## Out of scope

Symmetry reduction, multi-threading, Python bindings, shipping PDBs in the wasm,
changing Thistlethwaite/Kociemba defaults.

## Reporting

Files, table sizes/times/RSS, h(superflip), superflip result (proved or not) with
node counts, random-cube results, and any design deviation. Under 900 words.
